About This Validation App

This app validates a fix for aspnetcore#68516 - navigating between pages that use different Blazor render modes.

Issue Details

In .NET 10, Blazor wrote metadata into pages as HTML comments for WebAssembly options, persisted component state, and JavaScript initializers. These were pulled into Blazor's logical tree during first render, then removed from the DOM. This left stale references.

When navigating with enhanced navigation across a render-mode boundary, the error occurred: 

Cannot read properties of null (reading 'insertBefore')

The visible symptom: address bar changed, but destination page didn't render. Recovery required a full reload or forceLoad: true.

Fix in .NET 11: Metadata comments are now skipped when building the logical tree, preventing stale references.

Validation Coverage

This app covers the required configurations:

  • Blazor Web App with Static SSR, Interactive Server, and Interactive WebAssembly
  • Pages with and without <PageTitle>
  • All render-mode transitions
  • Metadata comments (WebAssembly options, component state, JS initializers)

Expected Behavior: Clicking navigation links between any pages renders the destination page without errors.

Key Scenarios:

  • WebAssembly to Interactive Server (Home → Weather)
  • Navigation away from WebAssembly page without PageTitle (Counter → Home)
  • WebAssembly to Static SSR after visiting page without PageTitle (Counter → About)
  • All render-mode transitions in both directions

Use the navigation menu to test transitions between pages. Check the browser console for the validation error. Keep developer tools open to monitor for insertBefore errors.
